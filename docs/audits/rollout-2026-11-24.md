## The star prompt's good moment

Before: one `requestReview()` call (`RootTabView.scheduleReviewRequestAfterPositiveMoment`), triggered only by `ReviewPromptCoordinator.recordPositiveMoment()` from the two rating screens (`PhoneSessionView.saveEpisode`, `WatchRemoteSessionView.saveEpisode`). No launch, appear, tab or open-count trigger existed. But the moment was "not rated worse" (`reliefDelta >= 0`), which counted "The same" and, on the phone, a skipped rating (no rating reads as delta 0). Neither is a clearly positive result.

Now the only automatic moment is **a finished session the user rated "Better"**, on the phone or on the phone's watch-remote rating screen, when that session did not offer Pro. It is the core action finished with the outcome the app exists for, the user has just said so, and it is never the first launch (the tracker's 2nd-launch gate), never onboarding (`hasCompletedOnboarding`), never after a bad result, and never after a paywall (a session that offers Pro does not record a moment). The rating screen closes the session cover; `RootTabView` waits 3 seconds, then re-checks that no sheet, alert, cover, after-session paywall, Duo pane paywall or new session is up, that the app is active, and that RevenueCat's `rating_prompt` is not "off", before calling the system prompt and logging `rating_asked`. A blocked ask keeps the moment pending for the next "Better".

Tracker gates are unchanged: 2nd cold launch, 30 days between calls (stamped when the call is made), Settings' "Rate Queasy" (`?action=write-review`) ends the passive asks, "Send Feedback" never does. One addition from Mahj's tracker: a cooldown stamp in the future (a clock that ran ahead) no longer holds the asks shut. No enjoyment question, no pre-prompt, no button triggers it. AGENTS.md's Ratings paragraph names the new moment.

## Held for Jack

1. **Reminder toggle vs. iOS permission.** When notifications are off for Queasy in iOS Settings, `PressReminderService.refresh()` switches the stored reminder preference off, so turning notifications back on does not bring the reminders back. The fleet rule is to keep the toggle and restore the requests when permission returns. Recommendation: keep the preference on and show the existing "Notifications are off for Queasy" footer while iOS blocks them, so the reminders return by themselves. Not changed because it decides what the toggle shows.
2. **Packages come from the `default` offering, metadata from `current`.** `fetchProducts` sells the `default` offering's packages while the new reader reads `current` (so an Experiment's variant metadata is honoured). A wording test works today; an Experiment that changes packages or prices would not reach the paywall. Recommendation: leave it until a package test is wanted, then switch products to `current` in the same change. Not changed because it decides which plans are sold.
3. **Unknown trial eligibility reads as no trial** (`isEligibleForIntroOffer`, documented). Unchanged, as it decides when a trial is offered.
